# 天机 Wuji 分体控制与录制实机核查

核查时间：2026-11-19，约 11:20–11:25（北京时间）。通过现有专用 SSH 密钥，从本机有线网口 6.6.7.110 登录 nvidia@6.6.7.100，主机名 vision，架构 aarch64。Wi-Fi 地址仍为 192.168.90.121。

## 结论

这台机器人现有 Apex 配置确实包含 Wuji 手部录制白名单，但当前未发现向这些话题发布数据的节点，不能把“已配置白名单”当成“Wuji2 已接入或可以立即录制”。当前安装版本仍为旧版，Tool 配置为 dm，Robot、Teleop、Tool、Camera 均停止且禁用。

独立电脑通过 SDK 控手的方案可以另行实现；要由 Apex 录制，需要电脑或机器人上的桥接程序把手指目标和机械手实际反馈发布到机器人能收到的 ROS 2 话题。白名单是录制过滤配置，不会主动读取 SDK、手套或落盘文件。

## 对分体方案的实际含义

1. 电脑要能访问手套和机械手，SDK 控制回路才能成立。
2. 手部 ROS 发布桥接是当前缺失环节之一；不能只运行官方纯 SDK 遥操示例就期待 Apex 收到话题。
3. 桥接使用现场 Domain 22，并验证网卡、发现、QoS、准确话题名、消息类型和时间戳。既有白名单名可以作为接入候选；二代新名则需配置映射或增加白名单，不能只凭名字推定消息契约兼容。
4. 统一暂停、脚踏使能与手势需要对接天机接口。Wuji SDK 不会自动继承 eva-00 的启停状态机。
5. 本次未进行升级、配置编辑、服务启停、设备连接或运动，也未验证硬件是否已接入。当前结论针对软件、配置与可发现 ROS 图。

参考本地已核对实现：Wuji2/wuji-sdk/examples/python/retargeting/1.teleop_real.py 为实时单手纯 SDK 示例；1117 eva-00 中 wuji_glove_reader.cpp、pico_teleop_sender.cpp 和 wuji_service/main.cpp 已实现双手输入、目标发布、驱动和反馈，可作为后续适配依据。
